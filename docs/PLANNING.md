# 세 단어 서재 (가칭) — 기획 문서

> 랜덤 단어 10개 중 3개를 고르면, 그 세 단어와 맞닿은 책과 책 속 문장을 추천하는 웹앱.

## 1. 서비스 컨셉

- **한 줄 정의**: "오늘 나를 붙잡은 세 단어로 책을 만난다."
- 검색·베스트셀러 기반 추천이 아니라, **지금의 기분과 관심을 단어로 고르게 하는 우연성 있는 추천** 경험이 핵심.
- 결과는 책 제목만 주는 것이 아니라 **책 속 문장(인용문)** 을 함께 보여줘서, "이 문장 때문에 읽고 싶어진다"는 감각을 만든다.

### 확정된 기술/운영 방향
| 항목 | 결정 |
|---|---|
| 데이터 소스 | 자체 큐레이션 데이터셋 (JSON) — 서버·API 없음 |
| 단어 풀 | 감정·상황·개념·이미지 혼합 카테고리 |
| 스택 | React + Vite + TypeScript, 정적 SPA |
| 배포 | GitHub Pages (또는 Vercel), 유지비 0원 |
| 부가 기능 | 결과 카드 이미지 저장/공유 |

## 2. 핵심 사용자 플로우

```
[홈/인트로]
   ↓ 시작하기
[단어 선택 화면]
   - 단어 10개 칩 제시 (카테고리 혼합, 랜덤)
   - 최대 3개 선택 (선택/해제 토글)
   - "다시 뽑기" 버튼: 10개 전체 리롤 (선택했던 단어는 초기화)
   ↓ 3개 선택 완료 시 "책 찾기" 활성화
[결과 화면]
   - 추천 책 1권 (표지 영역·제목·저자)
   - 책 속 문장 (선택 키워드와 연결된 인용문)
   - 추천 이유 한 줄 (선택한 3개 단어와의 연결)
   - [다른 책 보기] 차순위 후보 넘겨보기 (최대 3권)
   - [카드로 저장] 결과를 이미지 카드로 다운로드/공유
   - [처음부터] 단어 선택으로 복귀
```

## 3. 단어 풀 설계

- 총 **80~120개** 단어, 4개 카테고리로 구성:
  - **감정·정서**: 위로, 설렘, 외로움, 용기, 그리움, 후련함 …
  - **상황·경험**: 이별, 여행, 퇴사, 첫만남, 기다림, 어른이 된다는 것 …
  - **개념·주제**: 시간, 자유, 죽음, 운, 정의, 습관 …
  - **사물·이미지**: 바다, 새벽, 편지, 골목, 겨울, 식탁 …
- **10개 추출 규칙**: 완전 랜덤이 아니라 카테고리별 층화 추출(예: 감정 3 + 상황 3 + 개념 2 + 이미지 2)로 매번 조합의 결이 다양하게 나오도록 한다.
- 데이터 무결성 규칙: **풀에 들어가는 모든 단어는 최소 2권 이상의 책과 태그로 연결**되어 있어야 한다(어떤 조합을 골라도 결과가 비지 않도록). 빌드 시 검증 스크립트로 강제.

## 4. 책 데이터셋 설계

`src/data/books.json` — 초기 목표 **50~80권**, 권당 인용문 2~4개.

```jsonc
{
  "id": "book-001",
  "title": "책 제목",
  "author": "저자",
  "publisher": "출판사",          // 선택
  "category": "에세이",           // 소설/에세이/인문/시 등
  "keywords": ["위로", "상실", "바다"],   // 책 전체 태그 (5~10개)
  "quotes": [
    {
      "text": "책 속 문장…",
      "keywords": ["위로", "바다"],       // 이 문장이 강하게 닿는 단어
      "source": "p.132"                   // 선택
    }
  ]
}
```

- 인용문은 저작권을 고려해 **짧은 발췌(1~3문장) + 출처 명기** 원칙.
- 장르 구성은 소설·에세이·인문 혼합을 기본으로 하되, 비율은 데이터 구축 단계에서 확정. *(→ 미확정 항목 §8)*

## 5. 매칭 알고리즘

1. **점수 계산**: 선택한 3개 단어와 각 책의 `keywords` 교집합 수를 기본 점수로.
   - 3개 일치 > 2개 일치 > 1개 일치.
   - 동점일 때는 랜덤 셔플로 매번 다른 책이 나올 여지를 남긴다.
2. **유의어 매핑**: `synonyms.json`에 관련어 테이블(예: 외로움 ↔ 고독 ↔ 혼자)을 두고, 직접 일치가 없을 때 관련어 일치를 0.5점으로 반영.
3. **인용문 선택**: 추천된 책의 인용문 중 선택 단어와 가장 많이 겹치는 `quotes[].keywords`를 가진 문장을 노출.
4. **폴백**: 3개 모두 걸치는 책이 없으면 2개 → 1개 일치로 단계적 완화. §3의 무결성 규칙 덕에 0건은 발생하지 않음.
5. **추천 이유 문구**: 템플릿 기반 생성 — 예: "'위로', '바다'를 고른 당신에게, 파도 앞에서 상실을 견디는 이 문장을."

## 6. 화면·컴포넌트 구조

```
src/
├── data/
│   ├── words.json          # 단어 풀 (카테고리 포함)
│   ├── books.json          # 책 + 인용문
│   └── synonyms.json       # 관련어 매핑
├── lib/
│   ├── drawWords.ts        # 층화 랜덤 10개 추출
│   ├── matchBooks.ts       # 매칭·랭킹·폴백
│   └── shareCard.ts        # 결과 카드 이미지 생성 (html-to-image)
├── components/
│   ├── WordChip.tsx        # 단어 칩 (선택 토글)
│   ├── WordBoard.tsx       # 10개 칩 + 다시 뽑기
│   ├── BookCard.tsx        # 결과 카드 (책 + 문장 + 이유)
│   └── ShareButton.tsx
├── pages/ (상태 기반 화면 전환, 라우터 불필요)
│   ├── Intro.tsx
│   ├── Select.tsx
│   └── Result.tsx
└── App.tsx
```

- 상태 관리는 `useState`/`useReducer`로 충분 (외부 상태 라이브러리 불필요).
- 스타일: Tailwind CSS. 모바일 우선(단어 선택·공유 모두 모바일 사용이 주가 될 것).
- 결과 카드 공유: `html-to-image`로 카드 DOM → PNG 저장 + Web Share API(지원 브라우저는 바로 공유 시트).

## 7. 개발 로드맵

| 단계 | 내용 | 산출물 |
|---|---|---|
| **M1. 코어 MVP** | 프로젝트 셋업, 단어 풀·책 데이터 초기 50권, 선택→매칭→결과 플로우 | 동작하는 웹앱 |
| **M2. 공유 카드** | 결과 카드 디자인, PNG 저장·Web Share, OG 태그 | 공유 가능한 결과 |
| **M3. 품질·배포** | 데이터 검증 스크립트, 반응형·접근성 다듬기, GitHub Pages 배포 | 공개 URL |
| **M4. 확장(선택)** | 데이터셋 100권+, 다른 책 보기 고도화, 히스토리(localStorage), 구매/도서관 링크 | — |

## 8. 확정 필요 항목 (다음 결정)

1. **서비스 이름** — 가칭 "세 단어 서재". 다른 후보: "단어책방", "세 단어의 책".
2. **책 장르 비율** — 소설:에세이:인문 = 4:4:2 를 기본 제안.
3. **결과 노출 방식** — 1권 크게 + "다른 책 보기"로 차순위 넘겨보기(제안) vs 처음부터 3권 나란히.
4. **초기 데이터 구축 방식** — 초안 데이터(책·인용문 후보)를 Claude가 생성 후 사용자가 검수할지, 사용자가 직접 리스트를 제공할지.
